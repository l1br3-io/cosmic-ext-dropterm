# Known issues

The current rough edges of running DropTerm - each with the upstream link where it is tracked. Rows marked *carried* predate the GPUI cutover and describe the pin's behavior; the manual checklist's rows re-verify them on the shipped binary.

- **Fractional output scales on COSMIC (carried, this pin)**: on a fractional-scale output (a 1.25 scale maps the surface at its full logical size), cosmic-comp accepts the layer surface and honors its geometry - the configure and the input region are right - but nothing visibly lands on screen. The spike banked the evidence on both compositors ([gpui-spike](research/gpui-spike.md), check 3's fractional rows) and the cutover carries the row: geometry honored, no visible output on COSMIC at this `gpui-pre` pin; integer-scale outputs (and sway at any scale) are unaffected. The display metadata both compositors report is integer-rounded besides - a 1.25-scale output reads as its floor - which is the same class underneath (the spike's `cx.displays()` finding); DropTerm's own surface never reads display metadata (the measuring pass takes granted bounds), so the rounding costs nothing today and the row records the pin's ceiling.
- **Clipboard on a hide/show cycle**: on Wayland a copied selection lives only as long as the client connection that offered it, and a clipboard store through the legacy `wl_data_device` path needs keyboard focus and a valid input serial at the instant of the copy - a drop-down terminal lives in exactly those states (surfaces recreated per hide, background shows without activation, focus lost to whatever you are about to paste into). The GPUI build's copy paths answer both: the pane's own copies ride GPUI's clipboard while it holds the keyboard (focus and serial are its by construction), and every focus-free write - an OSC 52 store from a background tab, the primary selection, the images panel's image copies - rides the data-control protocol (`terminal/clipboard.rs`), which needs neither. No never-closed anchor window is required at this pin (the spike's check-8 ruling: the gate is focus+serial, not surface liveness); `show_in_dock`'s toplevel is presence only, mapped for the dock and switcher to list. The compositor can still drop an offer when its output goes away - a monitor dropping off its link while asleep - in which case the copy on the clipboard at that moment is lost; nothing else is.
- **The paste cache is capped, not swept**: images pasted — clipboard bytes or a file copied in a file manager — land in `~/.cache/dropterm/paste/` and stay until the cap trims them: after each write the oldest files are evicted until the directory holds under 256 MiB (the resource-audit ruling, 2026-11-17), so the paste that just landed is never the one evicted but old pastes eventually give way. The images panel tolerates a trimmed file the same way it tolerates a hand-deleted one; the files are `0600`, owner-only, and an image over 32 MiB — clipboard offer or named file alike — is refused before it lands.
- **The status band's leading glyphs owe the font**: the ten segment glyphs (`⎇` branch, `⊞` grid, `▤` tab position, `◉` profile, `⧗` duration, `◐` progress, `⌂` path, `⇕` zoom, `▦` pasted images, `◷` clock) render as text in the terminal's own configured font, so a family that lacks a shape leans on the text system's fallback — a slightly mismatched glyph style is the worst case, tofu the rare one. The glyphs are constants in `dropterm/src/status_bar.rs`, retunable without touching anything else; everything structural about the band (layout, drop order, copies) is glyph-agnostic by construction.
- **Hiding a layer surface**: DropTerm hides by *destroying* its layer surface and creates a fresh one on the next show, rather than unmapping/hiding it in place. This sidesteps a compositor-connection-drop bug some other layer-shell clients (via gtk4-layer-shell) have hit on cosmic-comp when a surface is updated after its role is destroyed ([cosmic-comp#2159](https://github.com/pop-os/cosmic-comp/issues/2159)).
- **Custom shortcuts with Shift**: some Shift-modified custom shortcuts can fail to fire on COSMIC ([cosmic-epoch#2481](https://github.com/pop-os/cosmic-epoch/issues/2481)). Prefer an unshifted key such as `F12` for the toggle shortcut.
- **Modifier desync after heavy toggling (carried)**: a key press's modifier flags and the keyboard state that shapes its text are tracked in different places, and the destroy/recreate churn of the hide/show cycle can split them — a Ctrl+C arrives as the byte `\x03` while the flags claim no Ctrl, and plain typing keeps working, so the press dying silently reads as "Ctrl+C stopped working". The row was pinned on the libcosmic frontend, whose input arms answered by delivering whatever `text` actually carried (with a `warn` naming the disagreement); the GPUI input path carries its own translation and the parity checklist's input rows own its verdict. A fresh press-and-release of Ctrl resyncs the flags; opening a new tab in the same broken state tells a real desync (dead there too) apart from a foreground program that left its PTY in raw mode (the new tab's Ctrl+C works — that one is the program's to fix, or the tab's to close).
- **No GlobalShortcuts portal**: COSMIC doesn't yet implement the XDG `GlobalShortcuts` portal, so there is no way for DropTerm to register its own hotkey - it must be bound as a COSMIC custom shortcut (above).
- **No Flatpak packaging**: layer-shell and toplevel-management protocols aren't exposed to sandboxed (Flatpak) clients on cosmic-comp, so a true drop-down terminal isn't possible in a sandbox. This isn't planned until COSMIC exposes those protocols to sandboxes.
- **No layer-shell, no DropTerm (by design)**: DropTerm's drop-down surface is a wlr layer-shell surface, so compositors that offer no `zwlr_layer_shell_v1` — GNOME, a sandbox (the Flatpak row above), an X11 or otherwise Wayland-less session — cannot host it. DropTerm probes the session's registry at startup and exits with an error naming the missing protocol and linking here, instead of the old behavior: start, never surface, and answer `--is-visible` with true. COSMIC and sway advertise the protocol and are unaffected.
