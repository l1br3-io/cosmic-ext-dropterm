# Testing

How DropTerm is verified: headless unit tests for everything that needs no compositor, and this manual checklist for everything that does - runtime behavior is only testable on real COSMIC hardware. After building, check:
- [ ] First launch shows the overlay at the configured edge, focused and ready for input
- [ ] The bound shortcut hides and re-shows it
- [ ] Caret on show: every toggle-show paints the block cursor at the prompt in the first shown frame - before any keystroke; the same after a focus-loss hide (click another app with `hide_on_focus_loss` on, then re-toggle) and in a bash tab (no focus reporting - nothing else repaints the caret), and switching tabs paints the newly active tab's caret the same way
- [ ] A background job (`sleep 100 &`, shell history) survives a hide/show cycle
- [ ] Shell presence - hidden (the default): while DropTerm runs, shown or hidden, the window switcher and the dock list no DropTerm entry at all (the anchor is a layer surface no toplevel listing can see); the shortcut, the panel applet, and the CLI each summon it, and it never takes focus or input by itself
- [ ] Shell presence - dock mode: with `show_in_dock: true` (file or the Advanced toggle), the switcher and dock list one DropTerm window carrying the DropTerm name and icon, never an "unknown" label, and selecting it neither disturbs the running surface nor drops the clipboard binding
- [ ] Shell presence - the clipboard across both modes: copy in DropTerm, hide, focus another app, paste - the selection survives in hidden mode and in dock mode alike (the anchor's whole duty), and a mid-session flip (file or toggle, no restart) swaps the entry at the flip itself, costs exactly the selection on the clipboard at flip time, and copies made after the flip persist across hide/show again
- [ ] Rapid repeated toggles (double key-press) don't crash or duplicate the surface
- [ ] It appears correctly above a fullscreen window
- [ ] `Ctrl+Shift+C` / `Ctrl+Shift+V` copy/paste, and middle-click / `Shift+Insert` paste the primary selection
- [ ] Shift escape hatch under a mouse-grabbing program: in vim with `set mouse=a` (or tmux with `mouse on`), a plain drag stays the program's own selection while Shift+drag paints DropTerm's highlight and `Ctrl+Shift+C` copies it; Shift+right-click opens the context menu with Copy live; releasing Shift mid-drag keeps the gesture whole - the selection ends where the pointer stopped and the program sees no stray release; the wheel stays the program's even with Shift held (Shift+scroll scrolls vim, not the scrollback)
- [ ] `Shift+PageUp`/`PageDown` scroll the scrollback
- [ ] Numbered tab switching: with three tabs, `Ctrl+Shift+1`/`2`/`3` activate the first/second/third; `Ctrl+Shift+9` activates the last tab; `Ctrl+Shift+5` with three tabs does nothing (no wrap, no crash); bare `Ctrl+2` reaches the shell (only the `Ctrl+=`/`-`/`0` zoom cluster and its Shift-held forms bind)
- [ ] Zoom chords - premise then pairs: on a current build, unshifted `Ctrl+=` zooms in and `Ctrl+-` zooms out first (if either fails, stop and debug the event path - a binds fix cannot repair it); then the Shift-held forms - `Ctrl+Shift+=` and `Ctrl+Shift++` zoom in, `Ctrl+Shift+-` zooms out where the layout keeps `-` - and numpad `Ctrl+Plus` still zooms; on a US layout a Shift-held `Ctrl+-` arrives as `_` and still sends the shell 0x1F (readline undo keeps working, nothing stolen); `Ctrl+0` resets, and the status band's zoom segment shows only while zoomed
- [ ] Tab moves: `Ctrl+Shift+PageUp`/`PageDown` shift the active tab one slot, clamping at the list edges (no wrap); the moved tab stays active and focused, and `session.ron` records the new order
- [ ] Attention markers: with two tabs, `printf '\a'` in the inactive tab marks it `🔔`; `echo hi` in a third (inactive) tab marks it `•`; activating a marked tab clears its marker; the active tab never gains one; a `while true; printf '\a'; done` bell storm in an inactive tab leaves one steady `🔔` (a state, not a counter); markers follow their tabs through drag-reorder and survive the closing of neighbors
- [ ] Bell notifications: hide the terminal, `printf '\a'` inside it - exactly one desktop notification appears, naming the tab; a bell storm while hidden still yields exactly one; two different tabs belling while hidden yield two; showing and re-hiding re-arms the latch (a new bell notifies again); with the terminal visible a bell posts no notification (marker only); `bell_notification_enabled: false` silences them and the Behavior toggle round-trips to the config file
- [ ] Remote new-tab: with the app running, `cosmic-ext-dropterm new-tab` opens a tab in the running instance, places it per `new_tab_after_current` (default: after the active tab; see the placement item below), activates it, and shows the overlay; with the app not running, the first launch starts with that tab (alongside any restored session tabs)
- [ ] New-tab placement: with `new_tab_after_current: false` (written to the config file or flipped via the Behavior toggle, which round-trips to the file), `Ctrl+Shift+T`, `Ctrl+Shift+H`, the tab bar's `+`, and `cosmic-ext-dropterm new-tab` append the new tab at the end and activate it (test with a *middle* tab active - from the last tab, append-at-end and after-current are indistinguishable) - including a first-launch `new-tab` alongside restored session tabs; `duplicate-tab` still lands after the active tab; a restart keeps session order; with the key absent or `true`, every new tab lands after the active tab exactly as the default always did
- [ ] New-tab directory - the mode: with `new_tab_cwd: Default` (Behavior's dropdown or the file) and a live `default_cwd`, `Ctrl+Shift+T`, the tab bar `+`, the terminal and per-tab menus' plain New Tab, a bare `new-tab`, the startup tab, and the last-close respawn all open in that directory (`pwd` shows it); with `Inherit` (or both keys absent) every one of those surfaces behaves exactly as before (inheritance); `Ctrl+Shift+H`, `duplicate-tab`, profile launches, and session restore keep their own directories in both modes; an explicit `--cwd` wins in both
- [ ] New-tab directory - degrade and interplay: a dead `default_cwd` logs one `warn` per spawn and the tab opens in the pty default, while `Inherit` never warns (the key is not consulted); the Terminal card's "Default directory" row round-trips (Enter a path to set, empty to clear) and reopens showing the stored path; `default_profile` set → the profile's own live cwd owns every plain spawn in both modes and the fresh-tab respawn runs the profile
- [ ] Shell picker: the Terminal card's Shell dropdown lists this system's `/etc/shells` shells by basename (duplicates like `/bin/bash` + `/usr/bin/bash` collapsed to one row; an unreadable file offers the static bash/zsh/fish/sh quartet); a pick writes the full path and the next plain spawn runs it (`echo $0` names it) while a running tab is never re-launched; the stored value selects its row, a custom path typed in the free-text row below still works and selects no dropdown row; the row's description carries the `default_profile` note on the picker, the mode, and the directory
- [ ] `new-tab --cwd /tmp` opens the shell in `/tmp`; `new-tab --cwd /nonexistent` logs a `warn` and opens in the fallback directory; with the active tab cd'd somewhere, plain `new-tab` inherits that cwd
- [ ] `new-tab --cmd htop` runs htop instead of the shell (no config shell arguments inherited), and closing htop closes the tab; the `--cmd` tab is absent from `session.ron` after the next debounced save, while plain `new-tab` tabs are saved like any other
- [ ] Unrunnable-program degradation: a profile whose command names a program that is gone (e.g. `asdf`) - submenu pick, `+` dropdown row, `default_profile` spawn, and session restore alike - runs the command-then-shell wrap, so the shell reports the miss in-band ("command not found") above an interactive prompt and the tab keeps the profile's whole identity (colors, env, name on the band); a blank stored command line (hand-edited) logs one `warn` and opens a plain-shell tab (no profile name on the band; the preset's live cwd still applies); `new-tab --cmd asdf` degrades to a plain-shell tab as before; a config `shell` value that cannot exec skips to `$SHELL` then `/bin/sh` on the next plain spawn, and a session-recorded shell the system no longer carries restores onto the configured shell
- [ ] Profile submenu: with at least one profile configured, the terminal context menu's "New Tab" is a submenu - plain New Tab first, then one row per profile in config order - and each profile row launches that profile's command in its `cwd`; with zero profiles the menu renders flat exactly as before
- [ ] Profile command-then-shell (ruled 2026-10-12): a profile's command runs as a preamble of the resolved shell with an interactive tail (`sh -c "<command>; exec sh"`) every way it launches - submenu pick, `+` dropdown, `new-tab --profile`, `default_profile` plain spawns, session restore, and Switch Profile - so a one-shot command (`ls`) leaves its output visible above a prompt in the profile's colors and env, the band carries the profile name, and the session records the profile id; the tab never flash-dies on a finishing command, quitting a long-running profile program (q in htop) lands on the same prompt, and exiting that tail shell closes the tab exactly like a plain shell's exit (the last tab's close still respawns the never-empty default)
- [ ] Remote profile tab: `new-tab --profile web-prod` opens a tab running that profile, both in the running instance and at first launch; `--profile ghost` logs a `warn` and degrades to a visible plain-shell tab; `--profile` + `--cmd` is rejected by the CLI; an explicit `--cwd` beats the profile's own `cwd`
- [ ] Default profile: with `default_profile` set, `Ctrl+Shift+T` and a fresh startup run it as full profile tabs; a restart restores the profile tab by id, and a profile edited between save and restart launches the edited command; `duplicate-tab` still spawns a fresh shell
- [ ] Profile session semantics: a profile tab is saved to `session.ron` with its id and cwd while a `--cmd` tab stays absent; a saved id since deleted from the config restores a plain shell in the saved cwd
- [ ] Tab bar `+` visibility: the `+` shows beside the gear at the strip's right corner in every tab state (the 1-tab strip carries `+` and gear alone), on both edge placements and both themes; glyph, `New Tab` tooltip, and hover treatment read on light and dark panes alike
- [ ] Tab bar `+` click parity: a plain click on the `+` behaves exactly like `Ctrl+Shift+T` - with `default_profile` set it runs as a full profile tab, `cd /tmp` then click spawns in `/tmp`, and placement follows `new_tab_after_current` both ways (the placement item above covers the shared funnel)
- [ ] Tab bar `+` profile dropdown: with at least one profile configured, right-click on the `+` opens a dropdown listing `New Tab` first then one row per profile in config order (the context-menu submenu's composition); every profile row launches that profile, the plain row runs the default spawn; rows highlight on hover and the dropdown never clips at the surface's right corner
- [ ] Tab bar `+` zero profiles: with an empty profile list, right-click on the `+` no-ops (no visual change beyond the `+` itself) while the plain click still spawns
- [ ] Tab bar `+` dropdown dismissal: while open, a left press on a row picks it and closes; any other press - on the `+` itself (toggle), the strip, or away over the terminal - closes it with no side effects (no spawn, no tab select, no drag armed, nothing reaching the terminal)
- [ ] Tab bar `+` and strip geometry: a many-tab squeeze never underlaps the `+` or the gear (the row clips at the widened corner zone), drag reorder stays clear of both targets, and a `+` press during an inline rename commits the rename
- [ ] Tab bar `+` dropdown lifecycle: hide/show while the dropdown is open returns with it closed (the open state dies with the strip's tree)
- [ ] Status band - disc states and process name: with the default config the 28 px band renders at the free edge beside the grab bar; an idle tab shows the hollow ring plus the recorded shell's basename, `sleep 30` fills the disc and names `sleep`, `vim` names `vim`, and returning to the prompt restores the ring and basename; a wrapper-launched shell whose comm cannot be read falls back to the basename (honest, never blank)
- [ ] Status band - path and right cluster: `cd ~/src/oss` shows the `~`-collapsed path; squeeze it (a narrow `width_percent`, a long path, or profile + zoom set together) and the path elides from its left keeping the tail; the profile name shows only on profile tabs - a profile renamed or a `switch-profile-tab` respawn reflects on the band at the next event - and the signed zoom percent shows only while zoomed (`Ctrl+=` then `Ctrl+0` hides it)
- [ ] Status band - all four stackings: flip `edge` and `tab_position` through every combination - the band stays adjacent to the grab bar in each, the terminal's pixel height never changes across the flips, and the default `Auto` keeps the band between the tab strip's side and the grab bar
- [ ] Status band - colors: a scheme flip (settings drawer or config edit) recolors the band and its text on the next render through the shared pane derivation; text stays luminance-readable against both light and dark schemes, the right cluster reading dimmer than the path
- [ ] Status band - toggle and keybind: the Behavior page's Status bar card ("Show the status band") flips the band instantly with the terminal re-pinning its height the same frame; `Ctrl+Shift+B` flips identically (bare `Ctrl+B` still reaches the shell); a restart restores the persisted state; hand-editing `status_bar_enabled` while the app runs applies on the echo; a config directory from before the key loads with the band on
- [ ] Status band - font resolution: the band's text renders in the terminal's configured font at 12 px - compare its glyphs against the terminal's own cells; if the family did not resolve (fallback glyphs or a silent default), the sanctioned fallback is the default UI font at 12 px with every other token standing
- [ ] Status band - the grown segments: the grid segment (`80×24`) tracks a live resize (narrow the window and watch the columns count down, never dipping below one); the tab position (`2/5`) follows switches, new tabs, and closes; the branch segment reads a plain repo (`main`), a worktree checkout (its `.git` file indirection), a detached checkout (the commit's first seven characters), and stays absent outside repositories; the clock shows local `HH:MM` and ticks exactly on minute boundaries
- [ ] Status band - click-to-copy: click each segment in turn (path, branch, profile, grid, tab, zoom, clock, and the disc-and-name cluster) and paste elsewhere - every one lands the segment's *full* value (a path squeezed to `…/ced2` still copies `~/src/oss/l1br3/ced2`); the copy lands on release and the `✓` flash replaces the segment for ~800 ms before the value returns; the pointer cursor rides the segments and idles over the gaps; in-terminal copy binds (`Ctrl+Shift+C`/`V`) still reach the shell
- [ ] Status band - text selection (user-ruled 2026-10-11): press and drag across the band - the covered characters highlight (pane foreground at quarter alpha, following the cursor both directions) and the release copies exactly the selected display text (WYSIWYG: the elided path's `…` included; segments joined by single spaces; Ctrl+Shift+V into the terminal or middle-click paste both serve it - drag-selection also claims the primary selection); the highlight persists after release and clears on the next press; a drag held within 4 px stays a click (the full-value verb above); a drag confined to the gaps selects nothing
- [ ] Status band - per-segment toggles: each Behavior "Show ..." row hides exactly its segment on the next render (flip every one in turn); hiding the branch stops the `.git` reads and hiding the clock stops its tick (toggle the clock off mid-minute - the segment vanishes immediately and no further ticks land; on again it returns within a minute); a restart restores every persisted row; a config directory from before the keys loads with the full band
- [ ] Bar borders - placement through the four stackings: with both toggles on (the default), each bar shows exactly one 1 px hairline on its terminal-facing edge - walk every `edge` × `tab_position` combination: the strip's line follows the terminal (below a top strip, above a bottom strip), the band's stays on its side away from the grab bar; where the strip and the band adjoin (e.g. edge Top with tabs *Follow edge*, edge Bottom with tabs Top) the seam carries only the band's line - never a doubled line; the drag-reorder's lifted button may ride over the strip's line mid-drag (transient, verdict it here)
- [ ] Bar borders - live toggles and derived color: the Behavior page's "Show the tab bar border" (Tabs card) and "Show the status band border" (Status bar card) each flip their line on the very next frame - nothing resizes, the terminal's pixel height never changes; both lines read as subtle contrast lines on light *and* dark schemes (the 0.3-alpha verdict: retune `BORDER_ALPHA` in `src/tab_bar.rs` if either scheme reads too faint or too harsh) and a scheme flip recolors them on the next render; at `opacity` below 100 the lines still render; a fresh config directory loads with both on, and a config directory from before the keys gains both lines
- [ ] Status band - squeeze with the branch: at narrow widths the path elides first (tail kept); keep narrowing until the branch drops entirely - the priority is deterministic, path over branch, and the band never wraps or overflows
- [ ] Status band - grid on resize: at spawn dimensions the grid segment is absent (silent when default); drag the surface's height or narrow it and the segment appears showing the live `cols×rows`; resize back to the spawn dimensions and it vanishes; respawn the tab (Switch Profile on it) and it vanishes again - a fresh process starts default
- [ ] Status band - narrow-surface drop order: squeeze `width_percent` down and watch the band fit as one pass - the path elides first (tail kept), then segments drop one at a time in order (grid, tab position, zoom, profile, branch, clock), each drop buying the path back room (it re-expands between drops); the disc and process name are last standing, survivors keep their seats, and nothing wraps or overflows however narrow
- [ ] Status band - inline reveal: rest the cursor on an elided path - its display expands in place, the branch lending its seat (the full value when it fits, else the longest elision that does); the pointer cursor rides the displayed strip and a press copies the *full* value with the usual `✓` flash; hover any other segment or an un-elided path → pointer cursor only; leaving collapses instantly; walk it at both anchor edges (the reveal is pure in-band text - nothing floats, nothing clips)
- [ ] Status band - fresh on landing: run `sleep 30`, hide the surface, let the sleep exit, re-show - the disc is hollow on the first visible frame (the landing refresh read the exit), not one title-report later; the clock reads the current minute on landing too
- [ ] Status band - context menu surface and composition: right-click anywhere on the band - over a segment or a gap alike - opens the menu at the cursor on the terminal's side (walk both anchor edges; the bubble never overflows either end of the band); the composition is Copy · Copy All · Paste │ Zoom In · Zoom Out · Reset Zoom │ Hide Status Bar · Settings… - Copy muted on a gap press, Reset Zoom muted at base size and live once zoomed (`Ctrl+=` first); enabled rows highlight on hover, muted rows stay flat
- [ ] Status band - context menu copy and action semantics (status-menu criteria 2-3): Copy on a pressed segment lands that segment's *full* value (a path squeezed to `…/ced2` still copies `~/src/oss/l1br3/ced2`) and flashes `✓` in place; Copy All lands every present segment's full value space-joined (paste elsewhere and compare against the band, absent segments skipped); both write the clipboard only (middle-click paste serves the drag selection, not the menu); Paste, the zoom trio, Hide Status Bar, and Settings… behave exactly like their keybinds (`Ctrl+Shift+V`, `Ctrl+=`/`Ctrl+-`/`Ctrl+0`, `Ctrl+Shift+B`, `Ctrl+Shift+I`)
- [ ] Status band - context menu dismissal, lifecycle, and the unified press (status-menu criteria 4-5): while open, any press closes it with no side effects unless it picks an enabled row (nothing reaches the terminal under it; a keybind still passes through - `Ctrl+Shift+T` while open spawns and the rows re-derive); hide/show while open returns with it closed; and the press unification - a click under 4 px of travel on any segment copies its full value (before, every click read as a drag once the band sat mid-column), a crossing drag still selects WYSIWYG, and the pointer cursor rides the segments again
- [ ] Status band (command-lifecycle) - live elapsed: run `sleep 30` and watch the duration segment beside the process name count once per second (`0:04` → `0:05` → …) - the tick alone drives it, nothing prints; `cargo build` counts the same way; past the hour the shape is `1:00:00`
- [ ] Status band (command-lifecycle) - frozen pair and freshness: when the command finishes the reading freezes as `cargo 2:41` (the finished command's name beside its duration - the process segment already shows the shell again) and stands until the next command starts; clicking the segment copies the same string with the usual `✓` flash; a second command freezes fresh
- [ ] Status band (command-lifecycle) - honesty: a profile tab whose initial command wraps into its shell at spawn shows no duration for that command (start unwitnessed); a terminal switched to mid-run shows no live elapsed until its own next command; a respawned tab (Switch Profile) starts clean
- [ ] Status band (command-lifecycle) - lifecycle: hide the surface mid-run and re-show - the elapsed resumes honestly (no jump past the wall clock, no reset); after a finish, a hide, or a toggle-off the tick stands down within a second (no further counts land); the "Show the command duration" toggle off returns exactly the pre-segment band, on mid-command shows the live elapsed immediately - and both persist across a restart
- [ ] Status band (status-scrolled) - the chip appears and counts: in a busy terminal (output still flowing) scroll up with the wheel - the dim `↑N` chip appears in the right cluster between the zoom and the clock and its count tracks the distance scrolled; scroll back down and the count shrinks, reaching nothing at the bottom
- [ ] Status band (status-scrolled) - the jump click: click the chip - the viewport lands at the bottom and the chip vanishes the same frame; no clipboard write lands for it (paste elsewhere: the previous clipboard stands) and no `✓` flash - the jump is the whole verb; the context menu opened over the chip shows its Copy row muted (no value to copy) and carries no chip row of its own
- [ ] Status band (status-scrolled) - absent at bottom and under pressure: an at-bottom terminal shows nothing (a fresh terminal, a respawned tab, and the moment after a jump); squeeze `width_percent` down - the chip drops after the command duration and before the clock
- [ ] Status band (status-scrolled) - the toggle: the Behavior page's "Show the scrolled-back lines" row hides the chip outright (scroll up: nothing appears; on again it returns at the next event) and persists across a restart; a config directory from before the key loads with the chip on
- [ ] Status band (status-remote) - the stand-in shows: `ssh` to a real host from a tab inside a git repo - the path's seat shows the command's destination token exactly as typed (`user@host`, a bare alias), the branch disappears (both stale the moment ssh started), and the process segment keeps its honest `● ssh`
- [ ] Status band (status-remote) - flagged ssh and the copy verb: `ssh -p 2222 box` (or `-i key`, any option with a value) shows the host token, the option values skipped; click the stood-in path - the token copies whole with the usual `✓` flash (the token is the value)
- [ ] Status band (status-remote) - exit restores: exit ssh - the local path and branch return at the same snapshot event (the next prompt redraw), never mid-session; an argv that cannot certify a destination (a wrapper, a mangled invocation) leaves the local path standing rather than a guessed host
- [ ] Status band (status-select) - double-click select: double-click a rendered segment (the path, the branch, the clock) - its whole display text highlights (persisting until the next press) and the release copies exactly it to clipboard and primary, WYSIWYG (an elided path selects its elided display); no `✓` flashes - the highlight is the feedback
- [ ] Status band (status-select) - the single click is untouched and the verbs compose: click the same segments once - each still copies its full un-elided value with the usual `✓` flash; then click-then-double-click over one segment - the first release copies the full value, the second press-and-release selects the display (the terminal's own click-then-word-select rhythm)
- [ ] Status band (status-select) - middle-click paste: middle-click anywhere on the band - over a segment and over a gap - the clipboard pastes into the narrated terminal (the context menu's own Paste verb); a prior drag or double-click selection still serves middle-click paste as before, and the band's hidden state kills both idioms with the tree (no keys added)
- [ ] Status band (status-hover) - the tint: rest the cursor on any rendered segment and a quiet fill covers exactly that segment's strip - the same rect clicking copies from, rounded like the context menu's own rows - following the cursor segment to segment and vanishing with it (no fade, no layout motion); it reads at the menu's hover weight on light and dark schemes alike (the pane foreground's own hue, never a new one)
- [ ] Status band (status-hover) - gaps and absences tint nothing: the gaps between segments (the cursor already idles over them), a segment hidden by its toggle or squeezed out by a drop, and the cursor away from the band each leave the strip unpainted
- [ ] Status band (status-hover) - a selection owns the visual: press and drag across the band - the selection highlight paints and no hover tint does, through the drag and the persisting highlight after release; the next press (which clears the selection) hands the visual back
- [ ] Status band (status-hover) - the scrolled chip hovers like any segment: rest the cursor on the `↑N` chip - the tint covers its strip exactly as any segment's (its cursor already says Pointer) and the jump verb stands unchanged: the click still lands at the bottom with no clipboard write
- [ ] Status band (status-hover) - the open menu owns hover: open the context menu and rest the cursor on the bubble's rows - the bubble's own hover highlight is the only one; no band segment tints while the cursor rests over the bubble
- [ ] Status band (status-activity) - the hidden echo arms the halo: run `echo hi` in the active tab, hide the surface before it lands, then show it - a thin red ring circles the process disc; it survives the show and persists through further shown output (no timed expiry, no pulse - the toast expires, the halo does not)
- [ ] Status band (status-activity) - the touch clears: with the halo showing, a keypress into the terminal clears it that frame; arm it again and each of a paste, a wheel scroll, and a click in the terminal pane clears it in turn; output alone (another hidden echo) never clears it
- [ ] Status band (status-activity) - the chip's jump is a touch and the switch clears both: arm the mark, scroll up, then click the `↑N` chip - the jump clears the halo; arm it again and switch tabs by keybind while hidden, then switch back and show - the mark is gone (the switch cleared it; the show never does; both tabs' latches clear at a switch)
- [ ] Status band (status-activity) - composition and geometry: the ring composes with the filled disc (a running command) and the hollow disc (idle) without covering either; with the process segment toggled off it stands alone at the band's left edge, and no segment rect ever moves - the halo is not a click target (the disc's click still copies the process name)
- [ ] Status band (status-activity) - the toggle and the red: the Behavior page's "Show the missed-activity halo" row hides it outright (key off means never rendered) and persists across a restart; a config directory from before the key loads with the halo on; the red tracks the scheme - the bright red on a dark strip, the plain red on a light one (flip schemes to watch it flip) - and a scheme that defines no red degrades to the pane foreground's monochrome, never an invented hue
- [ ] Status band (status-exit) - the verdict lands beside its cost: with the fish-4 integration active (fish ≥ 4 emits the 133;D mark natively), run `false` - the chip `✗1` appears beside the frozen duration (`cargo 2:41 ✗1` shape); a `true` finish shows nothing (success is the unmarked default); the next command's start clears the chip with the frozen pair
- [ ] Status band (status-exit) - without integration nothing changes: a shell with no 133;D emission (plain bash before any rc hook) renders the band exactly as before - no seat, no gap, no verdict guessed from a bell or a title
- [ ] Status band (status-exit) - the red and the copy: the chip's red matches the scheme's own red - bright on a dark strip, plain on a light one - and tracks a scheme flip on the next render; clicking the chip copies the bare code (`1`) and flashes its `✓`; the context menu's Copy row does the same
- [ ] Status band (status-exit) - the chip drops after its duration: squeeze the band (narrow surface, many segments) - the exit chip yields after the duration and before the scrolled chip, survivors keeping their seats
- [ ] Status band (status-exit) - the toggle: the Behavior page's "Show the exit status" row hides the chip and its sampling on the echo and persists across a restart; a config directory from before the key loads with the chip armed
- [ ] Status band (osc7-cwd) - the report outranks the guess: with an OSC 7 integration active (the fish/zsh/bash snippets in the status-bar page), `cd` around - the path segment tracks the reported cwd live, `~`-collapsed on this machine, and clicking it copies the displayed value whole
- [ ] Status band (osc7-cwd) - the remote truth: ssh into a host whose shell reports OSC 7 and `cd` there - the path renders `host:path` verbatim (no `~` collapse - no remote home is known) and the git branch hides while the report stands; exiting the ssh leaves the last report standing until a newer one or a respawn replaces it (the documented peer lifetime)
- [ ] Status band (osc7-cwd) - without integration nothing changes: a shell with no OSC 7 emission (plain bash before any rc hook) renders the path exactly as before - `/proc` cwd, ssh stand-in, branch - byte-identical
- [ ] Status band (osc94-progress) - every state by hand: run the printf driver block from the status-bar page in a shell - `42%`, the moving `84%`, `…` (indeterminate owns the chip), the red `42%` on error, the plain paused `42%`, the `!` after a clear-then-error, and the final clear's absence each render in order, beside the exit chip
